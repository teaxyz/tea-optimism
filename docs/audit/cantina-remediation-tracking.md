New regression tests: `create_evm{,_with_inspector}_installs_multiplier_on_tea_chain`, `create_evm_leaves_multiplier_none_off_tea`, `proofs_history_flag_is_rejected`. The receipt-`l1Fee` cluster was the one remaining open RPC gap; it is now **Addressed in #28** (133/161/170), which makes `OpReceiptConverter` apply the GasPriceOracle multiplier (sampled at parent-block state to match execution). **176**'s receipt leg is thereby closed. **2026-06-01 (design clarification):** 147's one-block freeze is **by design** — the multiplier is sourced from an AMM pool oracle (TeaWAP/Velodrome) whose spot price is flash-loan-manipulable within a tx/block, so charging must use the pool's *settled* prior-block state, never an intermediate same-block value. 147 and its composite **176** are reclassified **Won't-fix**; **171** is likewise **Won't-fix** (the ETH-mode CGT-backing drain is architecturally precluded by Tea's CGT-mode portal). **164** (eth_simulateV1's L1-attributes-deposit omission) is reclassified **Won't-fix** — does-not-matter (stock-upstream, RPC-simulation only, no consensus/funds impact); its multiplier consequence is already covered by #21's factory. **2026-06-01 (review pass):** several findings were further re-dispositioned with the design rationale: **136/140** (hardfork clobber) → Won't-fix (no standing change — intrinsic to fork adoption, disarmed, and recoverable via the EL backup); **184/187** (Go op-program) → Won't-fix (op-program is not Tea's fault-proof client — kona is); **134** (fresh-CGT backup) → Won't-fix (by design — fallback until a pool exists); **164** → Out-of-scope (stock-upstream reth simulateV1 behavior). > **2026-06-07 (re-scan follow-up):** Cantina re-scan #4 surfaced **TEAO1-193**, a defect in #19's *own* subkey-eligibility gate: `subkey_can_sign` unioned the `sign` flag across every retained binding via `any()`, so a stale signing-capable binding kept a subkey eligible even after a later valid non-signing re-binding or a revocation — letting a caller who still controls the subkey material make `0x0696` return `bytes32(1)` for an effectively-revoked/re-bound subkey. **Addressed in #19** (and mirrored into the consolidated `tea-precompiles` copy in #27): eligibility now resolves the *effective* (latest-by-creation-time) `SubkeyBinding`/`SubkeyRevocation` packet and honors only that one, failing closed on equal-timestamp ties (revocation > non-signing > signing). Regression test `test_subkey_effective_binding_overrides_stale_signing` asserts a retained older signing binding can no longer re-enable a re-bound non-signing subkey, with a positive control where the signing binding is the effective one. Counts: **26 / 3 / 10 / 23**.

> **2026-06-07 (TEAO1-143 addressed):** **Finding 143 moves Deferred → Addressed (#32).** The interop host's `L2BlockData` re-execution built its executor with `OpEvmFactory::default()` while the interop client replay uses the Tea-aware `FpvmOpEvmFactory` — so for any fee-paying block where the multiplier ≠ 1x the host left `ctx.chain.l1_cost_multiplier` unset, charged raw OP L1 fees, and persisted an execution-derived header the client replay would never reproduce (it also skipped the accelerated-precompile hint path). The fix routes the host re-execution **and** both client paths through one shared selection point, `kona_client::fpvm_evm::fpvm_op_evm_factory`, so the host uses the *same* `FpvmOpEvmFactory` as the client and the factory choice cannot drift between replay paths; it also adds a guard that refuses to store preimages unless the rebuilt optimistic header hash matches the requested disputed hash. Regression PoC `POC_interop_host_raw_op_fees_8404aeeb` pins the factory divergence at 42x. Merged into the #29 integration branch. (De-duplicating the EL/FPVM `tea_l1_cost_multiplier` wrapper is intentionally left out: it is coupled to the `is_tea` chain-gate from #21/TEAO1-132 and belongs with that change.) This closes the last open item of the fault-proof-hardening class — **181** remains the sole Deferred finding. Counts: **27 / 1 / 10 / 24**.
