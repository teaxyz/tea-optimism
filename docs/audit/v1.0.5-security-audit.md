# v1.0.5 Security Audit — New-Issue Hunt

Branch: `integration/security-v1.0.5` vs base `origin/tea-reth` (merge-base `2e8062ce62d4`).
Surface: 85 files, +7483/−1001 (rust EL/FPVM, op-reth payload/txpool/rpc/node, contracts).
Method: 6 parallel adversarial reviewers over the consensus-critical areas, each hunting
forgery / panic-halt / DoS / EL≡FPVM divergence / fund-loss / data-exposure and designing
PoCs; critical candidates then verified directly against code + deployed infra.

## VERDICT — I would bet money v1.0.5 introduces no critical new issue.

No newly-introduced path was found that breaks **consensus/proof soundness**, loses or steals
**funds**, forges a **signature**, halts the **chain**, or exposes **sensitive data**. The
big-ticket risks were verified *sound*, not merely "not found." The genuine findings are Low/
Info, latent on always-CGT mainnet, or operator-misconfig hardening — none cross the
"critical functionality or data" bar.

## Recommended (non-blocking) follow-ups
1. Backlog: make GPG gas work-proportional + cap blob/subkey/sig counts (shared `gas` mod, EL+FPVM) — pre-existing, coordinate as a consensus param change.
2. Mirror the `cgt_enabled` gate in pool/receipt/trace paths (finding 3) so the 3 paths can never disagree.
3. Validate `--proofs-history.*` numeric args (reject 0 interval/window) and only register debug overrides when the `debug` namespace is enabled (finding 2/5).
4. RAII-clear the `tea-trace-ctx` handoff (finding 4); regenerate the storage-layout snapshot (finding 7).

## Bottom line
v1.0.5 hardens real vulnerabilities (GPG F-1 consensus-halt, conditional-tx enforcement,
interop host parity, storage-layout immutability) **without introducing a critical regression**.
EL/FPVM determinism, fund safety, and signature soundness hold under adversarial review.
Ship-safe from a security standpoint; the Low/Info items are correctness/hardening follow-ups.
