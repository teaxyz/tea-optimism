### Cause A — the `0x0698` test-bug (#19/#22/#23/#24/#30/#32)
`tea-reth/tests/evm_integration.rs::test_wrong_address_is_not_precompile` called
`0x…0698` expecting empty output — but `0x0698` **is** the SSHSIG precompile
(`evm/factory.rs:161`), so it correctly returns non-empty. The test's premise was wrong.
Fix: use `0x0699` (genuinely unregistered). Production registration (0x0696/97/98) is
unchanged and correct; #20/#27 already carried the `0x0699` fix.

### Cause B — the CGT fixture gap (#21)

`isCustomGasToken`, so #21's own TEAO1-165 gate correctly returned `None`. Fix: seed the
CGT flag (models the always-CGT Tea chain). **Proven not a mask** — the gate is exercised
both ways and all pass:

## 3. The one real latent bug this surfaced

`tea-precompiles/src/gpg_verify.rs` lacked overflow-safe offset decoding — a crafted
`u64::MAX` offset would panic inside the precompile (a **consensus halt**). #19's GPG
hardening never covered it (that case is the separate 2026-05-19 F-1 audit, fixed in #27),
and with no test CI nothing exercised it. Integration carries the `checked_add` decoder
(`header_end`/`data_end` + `usize::try_from`) and the regression test
`test_gpg_verify_crafted_offset_no_panic`.
